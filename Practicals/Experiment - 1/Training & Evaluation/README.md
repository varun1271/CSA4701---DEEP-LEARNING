# Module 3: Training & Evaluation

## 1. Module Overview
Module 3 benchmarks and evaluates the vector dot product and matrix multiplication recommendation engine on held-out test data.

This module answers the core system questions:
1. **Computational Speedup:** How much faster is matrix multiplication $\mathbf{U} \mathbf{P}^T$ compared to sequential vector dot product loops?
2. **Recommendation Accuracy:** How effectively does matrix-multiplication retrieval identify relevant products for customers across rank cutoffs $K \in \{1, 3, 5, 10, 15, 20\}$?
3. **Qualitative Relevance:** Do recommended items match the aesthetic and category profile of individual customers?

---

## 2. Computational Benchmark: Loops vs. Matrix Multiplication

To demonstrate the power of matrix multiplication over sequential dot products, latency was measured across catalog sizes from $N = 50$ to $N = 1,000$ products for 100 test customers:

| Catalog Size ($N$) | Sequential Dot Product Loop (ms) | Vectorized Matrix Mult $\mathbf{U}\mathbf{P}^T$ (ms) | Measured Speedup Factor |
| :--- | :--- | :--- | :--- |
| **50 products** | 16.66 ms | 0.017 ms | **960.1x** |
| **100 products** | 32.36 ms | 0.023 ms | **1,427.4x** |
| **200 products** | 65.43 ms | 0.036 ms | **1,806.9x** |
| **300 products** | 95.79 ms | 0.282 ms | **339.8x** |
| **400 products** | 131.45 ms | 0.362 ms | **363.0x** |
| **500 products** *(Our Catalog)* | **161.14 ms** | **0.415 ms** | **388.6x** |
| **800 products** | 261.49 ms | 1.685 ms | **155.2x** |
| **1000 products** | 327.40 ms | 2.514 ms | **130.2x** |

### Why is Matrix Multiplication ~388x Faster?
1. **Elimination of Python Bytecode Overhead:** The loop version executes $100 \times 500 \times 20 = 1,000,000$ interpreted scalar operations with dynamic type checking and memory pointer dereferences.
2. **CPU Cache Hierarchy & Locality:** Matrix multiplication utilizes optimized GEMM (General Matrix Multiply) subroutines from BLAS/LAPACK. It blocks the matrices into sub-tiles that fit into L1/L2 CPU caches, minimizing RAM access stalls.
3. **SIMD Vectorization (AVX2 / AVX-512):** Modern processors execute up to 8 single-precision or 4 double-precision multiply-accumulate operations in a single clock cycle using vector registers.
4. **Hardware Thread Parallelism:** BLAS automatically distributes matrix tiles across multiple physical CPU cores.

## 3. Top-K Recommendation Evaluation Metrics

Evaluation metrics were computed for rank cutoffs $K \in \{1, 3, 5, 10, 15, 20\}$ against held-out customer interactions:

| Cutoff $K$ | Precision@K | Recall@K | NDCG@K | Hit Rate@K | MRR@K | Catalog Coverage (%) |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **$K = 1$** | 0.2300 | 0.0767 | 0.2300 | 0.2300 | 0.2300 | 14.0% |
| **$K = 3$** | 0.1500 | 0.1500 | 0.1657 | 0.4300 | 0.3117 | 31.4% |
| **$K = 5$** | 0.1540 | 0.2567 | 0.2277 | 0.6000 | 0.3507 | 44.2% |
| **$K = 10$** | 0.1550 | 0.5167 | 0.3449 | 0.9000 | 0.3926 | 68.0% |
| **$K = 15$** | 0.1547 | 0.7733 | 0.4406 | 1.0000 | 0.4011 | 78.8% |
| **$K = 20$** | 0.1500 | 1.0000 | 0.5157 | 1.0000 | 0.4011 | 87.0% |

### Key Metric Insights:
- **Hit Rate reaches 90% at $K=10$ and 100% at $K=15$**, meaning customers find relevant products within their first recommendation viewport.
- **Recall reaches 100% at $K=20$**, capturing all ground-truth preferred items.
- **NDCG@K climbs steadily to 0.516**, verifying strong ranking quality with highly relevant items appearing at top ranks.
- **Catalog Coverage reaches 87.0%**, demonstrating healthy catalog exploration without monopolization by a few popular items.
